# 転職準備プロジェクト（テンプレート）

応募書類の作成と面接準備を、**ひとつの事実の集まり（`input/`）から**作るための枠組みです。
書類と面接の回答が食い違うと一発で信用を失うため、出所を `input/` に一本化しています。

**はじめての方は [`_START_HERE.md`](_START_HERE.md) を読んでください。** 何から埋めればよいか、順番に案内します。

```
Resume/
├── _START_HERE.md     ← 使い方の入口。最初に読む
├── README.md          ← いまこれ。全体の地図
├── documents/PROMPT.md ← 書類生成の詳細ルール（叩き台）
├── LESSONS.md         ← 教訓を蓄積する場所（意図的に空。使いながら自分の教訓を書き足す）
├── BACKLOG.md         ← 「今はやらない」と決めたことを理由とともに記録する場所（意図的に空）
│
├── input/             ← 事実の唯一の出所。書類も面接もここを読む
│   ├── profile/         経歴が動いたときだけ更新（今は空の雛形）
│   ├── apply/           応募先ごとに書き換える（今は空の雛形。志望動機は3層構成、詳細は`apply/`内の各ファイル参照）
│   ├── sources/         LinkedIn / Credly / MS Learn 等の原本PDFを置く場所（任意）
│   └── assets/          証明写真を置く場所（`photo.jpg`という名前で置くと自動で埋め込まれる）
│
├── documents/         ← 応募書類（生成物）
│   ├── PROMPT.md        生成プロンプト（運用ルールの詳細はここ）
│   └── output/
│       ├── md/            md が唯一の情報源。pdf は md から機械生成。
│       │                  build_pdf.pyが期待する見出し構成だけの空の雛形が最初から置いてある
│       └── pdf/           （空。build_pdf.py実行で生成される）
│
├── interview/         ← 選考の進行管理と面接準備
│   ├── 選考一覧.md        全応募先のダッシュボード（今は空）
│   ├── INTERVIEW_PROMPT.md
│   ├── _template/       新しい応募先を作るときの雛形
│   └── companies/       応募先ごとのフォルダ（今は空。応募が決まったら`_template/`からコピーして作る）
│
├── scripts/
│   ├── build_pdf.py     md → PDF 生成（日本語フォント埋め込み）
│   └── check.py         整合性チェック
│
└── templates/          ← 会社非依存の再利用モジュール（推薦文・JD突き合わせ・年収交渉・模擬面接・チェックリスト）
```

## よく使う操作

| やりたいこと | 言うこと | 触るファイル |
|---|---|---|
| 書類を作る | 「履歴書を生成して」 | `input/` を埋めてから |
| ある会社に応募する | 「◯◯社向けに作って」 | `input/apply/07_応募先.md` に JD と接尾辞を記入 |
| 資格を更新する | 「資格を更新して」 | `input/sources/` の PDF を上書き |
| 面接準備を作る | 「◯◯社の△次の準備をして」 | `interview/companies/*/rounds/` |
| 面接を記録する | 「面接の記録を書きたい」 | `interview/companies/*/rounds/` |
| 新しい応募先を足す | 「◯◯社の選考を管理したい」 | `interview/_template/` からコピー |
| 提出前の確認 | 「チェックして」 | — |

## コマンド

```bash
python3 scripts/build_pdf.py   # PDF を生成
python3 scripts/check.py       # 提出できる状態か検証
```

`check.py` が見るもの:

- md と pdf に**同じ数値**が入っているか、pdf が md より古くなっていないか（`scripts/check.py`の`KEY_FACTS`に自分で追加すると精度が上がります）
- 学歴・職歴・資格の**年月が時系列順**か
- 提出物に **★（未記入）** が残っていないか
- 「御社」「和暦」など**日本の書類での禁止表現**
- 資格の**有効期限切れ・期限間近**

## 設計上の注意（触るときに知っておくこと）

**md が唯一の情報源（single source of truth）。** `output/md/履歴書_{接尾辞}_ja.md` と `職務経歴書_{接尾辞}_ja.md` を直接編集すれば、
`python3 scripts/build_pdf.py` が内容をパースして pdf を生成します。html を経由せず、build_pdf.py 側に内容を
書き写す必要もありません。

**md を編集したら `python3 scripts/build_pdf.py` を忘れずに再実行**してください。忘れると pdf が古いままになります
（`scripts/check.py` が md と pdf の更新日時を比較して警告します）。

md の見出し構造（`## `/`### `/`#### `、`| 項目 | 内容 |` の表、`- key: value` の箇条書き）を大きく変えると
`build_pdf.py` がパースできなくなるため、既存ファイルの構造パターンを踏襲してください。表セル内の `**太字**` は
職務経歴書では黄色マーカー、履歴書では通常の太字として自動的に反映されます。

**PDF は HTML から変換しない。** `build_pdf.py` は reportlab で直接組版しており、html という中間形式を経由しません。

## このテンプレートについて

このテンプレートは、実際に転職活動でこの枠組みを使い込んだ結果できたものです。ただし、そのときに積み上がった具体的な教訓（`LESSONS.md`）や検討記録（`BACKLOG.md`）はあえて含めていません——他人の教訓をそのまま渡すと、あなたが自分で気づく機会を奪ってしまうためです。**渡しているのは中身ではなく、教訓を蓄積する仕組みと習慣**です。詳しくは`_START_HERE.md`「3」を読んでください。

`documents/PROMPT.md`・`templates/`配下のモジュールも同様に「叩き台」です。捏造しない・事実と解釈を分ける・input は正本で documents は取捨選択、という核となる原則以外は、自分のやり方に合わせて自由に書き換えてください。
