# JD突き合わせ・経歴ヒアリング

> いつ使うか（トリガー）: **新しい応募先の求人票（JD）を入手したとき**、または**「不足している経歴情報を洗い出したい」「JDとの適合度を確認したい」と言われたとき**。
> 判断原則: **数値はスコープを確定させる**（「誰の・何に対する数字か」を明示する）、**推測で事実を埋めない**（不明点は★で明示する）。詳細は`../../LESSONS.md`に自分の教訓として蓄積してください。
> 記入例はこのテンプレート単体には含まれません。実際に埋める際は`input/apply/07_応募先.md`の「応募戦略メモ」節（JDの要求と実績のギャップをどう埋めるか）が、このモジュールの成果物にあたります。

## このモジュールが解決すること

JDの要求と本人の経歴を突き合わせ、①完全に対応する実績がある項目、②部分的にしか対応しない項目、③材料が無い項目に分類する。②③についてはヒアリングで埋められないか検討し、埋まらない場合は「無いことをどう正直に、かつ不利にならない形で説明するか」の方針を決める。

**「材料を見つける」ことと「本人に何を聞くか」は同じ作業の裏表**——JDのギャップを分析した瞬間に、次に本人へ聞くべき質問がほぼ自動的に決まる。この一体化した流れがこのモジュールの核。

## 進め方

1. **JDから要求を抽出する**: 必須要件・歓迎要件を箇条書きでリスト化する
2. **経歴データと照合する**（`input/profile/04_職務経歴.md`・`05_スキル.md`等を参照): 各要件について
   - **完全対応**: 具体的な案件・実績で直接示せる
   - **部分対応**: 近い経験はあるが、そのままでは弱い、または別の言葉で語る必要がある
   - **材料なし**: 該当する経験が見当たらない
3. **ヒアリング質問を作る**（部分対応・材料なしの項目について）:
   - 「本当に無いのか」を確認する質問と、「実は別の形であるのではないか」を掘る質問の両方を用意する
   - 優先度をつける（JDの必須要件に直結するものを最優先）
   - ⚠️ 質問の答えが「無い」であっても構わない。**無いことが分かることには価値がある**（★のまま残せる。推測で埋めない原則）
4. **ヒアリング結果を反映する**: 経歴ファイル（`input/profile/`）に反映し、★を解除する。新事実は他の書類（`documents/output/md/`・`input/apply/06_志望動機_希望条件_{接尾辞}.md`・`input/apply/志望動機/`等）への伝播漏れが無いか横断確認する
5. **応募戦略を決める**: JDのどの要件を職務要約・自己PRの前方に配置するか、弱み（材料なし項目）をどう説明するかを`07_応募先.md`相当のファイルにまとめる

## 使うときの注意

- **ヒアリングは1回で終わらせない。** 最初のヒアリングで出てきた回答が、さらに別の材料を引き出すきっかけになることが多い（今回の discovery による課題再定義、10%バッファの判断等は、いずれも最初の質問への回答をさらに深掘りする中で出てきた）
- **本人が「弱み」と思っている点ほど、聞き方次第で強みに転換できることがある**（例: 「評価する側に立った経験」が「提案する側の視点に転用できる非対称な強み」に転換された）。ただし誇張はしないこと
