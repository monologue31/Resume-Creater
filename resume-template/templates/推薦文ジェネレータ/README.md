# 推薦文（リファラル）ジェネレータ

> いつ使うか（トリガー）: **リファラル応募で推薦文を用意する必要が生じたとき**。
> 位置づけ: リファラル応募での推薦文作成で確立した方法論を、**他社への応募でも再利用できる仕組み**として切り出したもの。
> 実例はこのテンプレート単体には含まれません。実際に使う際は`documents/output/md/推薦文_リファラル_{接尾辞}.md`（内部検討用）・`推薦文_参考資料_送付用.md`（送付用）として作成してください。
> 判断原則: **紹介者に、その人が裏付けられないことを書かせない**（関係の実態を先に確認する）、**作業ファイルと納品物は別物**（渡す相手が変わればファイルも変える）。詳細版の原則は [`判断フレーム.md`](判断フレーム.md)
> 空欄テンプレート: 内部検討用 [`テンプレート.md`](テンプレート.md) ／ 送付用 [`送付用テンプレート.md`](送付用テンプレート.md)
> 完成後の確認: [`チェックリスト.md`](チェックリスト.md)
> このファイルへの導線: `documents/PROMPT.md` 冒頭

---

## ⚠️ 作業ファイルと納品物の分離（最重要原則）

このジェネレータは**2種類のファイルを別物として出力する**。同じ内容を1ファイルにまとめない。

| | 内部検討用ファイル | 送付用ファイル |
|---|---|---|
| **目的** | 自分たち（本人・支援者）が判断するための作業記録 | 紹介者にそのまま渡すクリーンな成果物 |
| **含める内容** | 判断の経緯、不採用になった案とその理由、紹介者との関係性の分析、フォーム記入への指示、注意書き・★等の内部メモ | 簡潔な導入、紹介者が触れられる検証可能な事実、参考文案、「自由に使ってよい」という位置づけの一文のみ |
| **含めない内容** | （制約なし） | 検討の経緯・不採用案・関係性分析・「相手に書かせてはいけないことのリスト」・フォーム記入の指示 |
| **テンプレート** | `テンプレート.md` | `送付用テンプレート.md` |

**なぜ分けるか**: 検討の経緯（なぜこの案を採用したか、紹介者との関係をどう分析したか等）は自分たちの判断には必要不可欠だが、**それをそのまま相手に見せると失礼になったり、意図しない印象を与えたりする**——特に「紹介者がどこまで言えるかを値踏みした形跡」や「フォームの記入方法を指定する」ことは、相手の厚意に対して越権的に映る。**渡す相手が変わればファイルも変わる**、という原則をこの機能で徹底する。

## 使い方

「〇〇社への推薦文を作りたい」と言われたら、まず以下を集める。**特に2番目（紹介者との関係）が最重要**——これを確認せずに書き始めると、実態と合わない文案を作ってしまい、後で作り直すことになる（実際に今回そうなった）。

### 1. 応募先の情報
- 企業名・ポジション名・JD（`input/apply/07_応募先.md` 相当のもの）
- リファラルの提出フロー（本人が直接提出するのか、紹介者経由か、フォームの入力項目）

### 2. ⚠️ 紹介者の情報（最重要・最初に確認する）
以下を**本人に直接聞く**。曖昧なまま進めない。

| 確認項目 | 具体的に聞くこと |
|---|---|
| どう知り合ったか | 元同僚か、友人の紹介か、コミュニティ経由か、今回の応募で初めて話したか |
| 一緒に働いたことがあるか | 直接の同僚・上司部下だったか、それとも間接的な関わりのみか |
| 交流の頻度・深さ | 日常的にやり取りがあるか、年に数回か、今回のリファラルの過程で初めて話したか |
| 紹介者自身の経歴 | 本人と共通点があるか（同じ会社出身、同じ業界からの転身、同じ資格保有 等）。⚠️ **これが見つかれば最強の材料になり得る**（`判断フレーム.md`参照） |

この4点が分かるまでは、**具体的な文案を作らない**。関係が分からない状態で書いた文案は、後で全部作り直すリスクが高い。

### 3. 本人側の材料
- 提出予定のレジュメ（`documents/output/md/Resume_*.md` 等、日英いずれか）
- 応募先の要件と特に対応関係が強い実績（`input/profile/04_職務経歴.md` 等）
- 職種上の懸念点（例:「専門のプリセールス経験が無い」等、本人が引け目を感じている点）→ 紹介者にしか埋められない可能性がある

---

## 進め方

1. 上記1〜3を集める
2. `判断フレーム.md` の原則に沿って、紹介者が実際に言える範囲を見極める
3. `テンプレート.md`（内部検討用）をコピーして埋める（プレースホルダーは `{{ }}` 表記）。判断の経緯・不採用案・関係性の分析はここに残す
4. 内部検討用ファイルで文案が固まったら、**そこから`送付用テンプレート.md`を埋めて、送付用ファイルを別途作成する**。検討の経緯はコピーせず、確定した文案と最小限の導入文のみを転記する
5. `チェックリスト.md` で完成後に確認（内部検討の内容が送付用ファイルに混入していないかも含む）
6. 本人に提示し、承認を得てから**送付用ファイルのみ**を紹介者に渡す
