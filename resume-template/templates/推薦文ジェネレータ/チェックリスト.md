# チェックリスト — 推薦文完成後に確認すること

推薦文（文案）が出来上がったら、紹介者に渡す前に以下を確認する。1つでも「いいえ」があれば、渡す前に修正する。

## 内容の妥当性

- [ ] **紹介者が実際に同意できる内容か。** 特に「〜だと感じている」「〜だと思う」という主観的な判断の文が、紹介者本人の実感と一致しているか（本人の推測で書いていないか）
- [ ] **紹介者と本人の関係の深さに見合った書き方になっているか。** 浅い関係なのに継続的な観察を装う表現（「一緒に仕事をする中で」「話していると」等）が残っていないか
- [ ] **レジュメの事実を並べ直しただけになっていないか。** 紹介者にしか言えない角度（判断フレーム原則1・4）が中心になっているか
- [ ] **誇張・断定的な表現が無いか。** 「必ず成功する」等の断定ではなく、「〜だと考えている」という判断の表明に留まっているか

## 事実の整合性

- [ ] **本人のレジュメ・提出書類と数字・事実が矛盾していないか。** 特に金額・人数などスコープのある数字（「誰の・何に対する数字か」）
- [ ] **機密情報や実際の顧客名が入っていないか。** 提出書類側で匿名化している顧客名は、推薦文でも匿名のまま
- [ ] **プロジェクト名・社内コードネームなど、対外的に出すべきでない情報が混入していないか**

## フォーム・提出フローとの整合性

- [ ] **フォームの「How do you know this person?」等の選択肢が、文面の内容と矛盾していないか**
- [ ] **提出フロー（誰が入力・提出するか）を本人が把握しているか。** レジュメの受け渡し順序に影響する
- [ ] **添付するレジュメが最新版・確定版か**

## 位置づけの確認

- [ ] **「これは参考材料であり、紹介者が自分の言葉で書くのが本来の形」という位置づけが、紹介者に伝わる形で渡せているか**
- [ ] **本人が紹介者に渡すメッセージの文案がある場合、押し付けがましいトーンになっていないか**（紹介者は好意で引き受けてくれる立場であることを踏まえる）
- [ ] ⚠️ **送付用ファイルに、内部検討の内容が混入していないか**（README「作業ファイルと納品物の分離」参照）。具体的には以下が送付用ファイルに含まれていないことを確認する:
  - 不採用になった案とその理由・検討の変遷
  - 紹介者との関係の深さについての分析（「交流が少ないので〜」等）
  - 「紹介者に書かせてはいけないこと」のリスト
  - フォームのプルダウン選択等、紹介者の記入内容を指定する指示
  - ★・内部メモ

## 最終確認

- [ ] **本人が内容を確認し、承認しているか**（紹介者に渡す前の最終ゲート）
