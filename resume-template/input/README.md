# input フォルダの構成

更新のきっかけが違うものを混ぜないよう、3つに分けています。

```
input/
├── profile/   … 自分の経歴。経歴が動いたときだけ更新する
│   ├── 01_基本情報.md          住所・連絡先・在留資格など
│   ├── 02_学歴職歴.md          学歴・職歴の年表
│   ├── 03_免許資格.md          資格一覧（Credly / Microsoft Learn 由来）
│   ├── 04_職務経歴.md          案件ごとの詳細（職務経歴書の本体）
│   └── 05_スキル.md            技術スキル・語学・強み
│
├── apply/     … 応募先ごとに書き換える／増やす。応募のたびに触る
│   ├── 志望動機/                （2026-08-07新設）職種にも企業にも依存しない共通レイヤー
│   │   ├── 00_不変の軸.md       全応募共通の資質・軸・実績材料（更新頻度: 低）
│   │   ├── ロール_プリセールス.md  プリセールス職共通の志望理由の型（例: ServiceNow）
│   │   └── ロール_XXX.md        職種が増えたら追加（例: ロール_コンサルティング.md）
│   ├── 06_志望動機_希望条件_{接尾辞}.md  応募先固有の志望動機・自己PR方針・希望年収（応募先ごとに複数存在してよい）
│   ├── 07_応募先.md            求人票（JD）と応募戦略
│   ├── 08_参考求人.md          参考求人の一覧（対応不要・記録のみ）
│   └── 参考求人/                参考求人ごとの詳細（1求人1ファイル）
│
├── sources/   … 外部サイトからの原本 PDF。上書きすれば再読込できる
│   ├── LinkedIn_プロフィール.pdf
│   ├── Credly_バッジ一覧.pdf
│   └── MicrosoftLearn_資格証明.pdf
│
└── assets/    … 画像
    └── photo.jpg              証明写真（3cm×4cm）。置けば履歴書に自動で埋め込まれる
```

## 更新のしかた

### 経歴が変わったとき（転職・昇格・新しい案件）
`profile/` の該当ファイルを直接編集 → 「履歴書を生成して」

### 別の会社に応募するとき（同じ職種、例: 別のプリセールス求人）
`apply/07_応募先.md` に新しい JD を貼り、接尾辞を設定 → `apply/06_志望動機_希望条件_{新接尾辞}.md` を新規作成し、企業固有の志望動機を書く（`志望動機/ロール_XXX.md`は既存のものを流用） → 「履歴書を生成して」
※ 接尾辞が違えば、既存の他社版は上書きされません（`06`は接尾辞ごとに別ファイルとして共存する。異なる職種の応募先（例: プリセールス職とコンサル職）を並行する場合、志望動機の内容が矛盾するため、`06`単一ファイルの上書き運用ではなく「接尾辞ごとに複数ファイル共存」という設計にしている）

### 新しい職種で応募するとき（既存のロールファイルと矛盾する場合）
`apply/志望動機/ロール_{職種名}.md` を新設し、「なぜこの職種か」を書く。既存のロールファイルは書き換えない（矛盾する内容が同居しないように、職種ごとに別ファイルを保つ）

### 資格を取ったとき
1. ブラウザで Credly / Microsoft Learn を開き「印刷 → PDF に保存」
2. `sources/` の同名ファイルに上書き
3. 「資格を更新して」と指示

※ Credly と Microsoft Learn は JavaScript レンダリングのため、URL からの直接取得はできません。PDF 経由が確実です。

### LinkedIn の内容を反映したいとき
LinkedIn プロフィール → Resources → Save to PDF → `sources/LinkedIn_プロフィール.pdf` に上書き

## 記号のルール

- **★** … 未記入、または要確認の箇所。生成時にこの印が残っていると、書類にも `★` として出力されます（提出前に必ず潰すこと）
- 残っている ★ の一覧は、プロジェクト直下の `TODO.md` に優先度つきでまとめてあります
