# _START_HERE.md — はじめての方はここから

## 1. これは何か

これは、**転職活動（応募書類の作成・面接準備）を体系的に進めるための枠組み**です。

中心にある考え方は1つだけです: **事実の置き場所（`input/`）と、提出する書類（`documents/`）を分離する。**
事実を1箇所にまとめておき、そこから応募先ごとに必要な部分だけを取捨選択して書類を作ります。こうすると、
- 応募先が増えても、事実を何度も書き直さずに済む
- 書類に書いた内容と面接で話す内容が食い違わない（面接準備も同じ`input/`を読むため）
- 「この案件は前に別の応募先向けにどう書いたっけ」を探し回らずに済む

このプロジェクトは**AIエージェント（Claude Code 等）と一緒に使うことを前提**にしています。あなたが情報を`input/`に書き溜め、「履歴書を生成して」のように話しかけると、エージェントが書類を作ります。あなた自身が全部の書式を手で整える必要はありません。

## 2. これは「叩き台」であって「守るべきルール集」ではない

⚠️ **これは重要な位置づけの説明です。**

`documents/PROMPT.md`（書類生成のルール）や`templates/`配下の各モジュールは、**他人（元の作成者）が自分の転職活動の中で作ったもの**です。そのまま「従うべき正解」として使う必要はありません。**あなたの状況に合わせて自由に書き換えてください。**

ただし、**全部が自由に変えてよいわけではありません。** 以下の原則は、形式ではなく考え方そのものなので、変えずに引き継ぐことを勧めます:

- **捏造しない。** `input/`に無い経験・数字・資格を作らない。
- **事実と解釈を分ける。** 提出書類には事実だけを書き、意味づけ・売り込み方は口頭や`input/apply/`側の検討メモに留める。
- **`input/`は正本、`documents/`は取捨選択された提出用の別物。** 両者を混同しない。
- **「承認した」と「実際にファイルに反映されている」は別の状態。** 反映したと言う前に、実際にファイルの中身を確認する。
- **構造・仕組みを変える前に、影響を確認してから変える。** `ARCHITECTURE.md`はそのための材料。
- **顧客名・関係者名は匿名化する。** 匿名でも、規模や数字の組み合わせで特定され得ることに注意する。
- **理由を、結論とともに残す。**（次の3節で詳しく説明します）

一方、**JIS履歴書の細かいレイアウト、職務経歴書のセクション順序、チェックリストの項目、模擬面接の具体的な進め方**などは、**元の作成者がそのとき必要だったから選んだ「一例」**です。あなたの状況（応募する国・業界・書式の慣習）に合わせて、遠慮なく書き換えてください。

## 3. `LESSONS.md`・`BACKLOG.md` — 中身ではなく「仕組み」を受け取ってください

`LESSONS.md`と`BACKLOG.md`は、**意図的に空の状態で渡しています。**

元のプロジェクトでは、実際の転職活動を進める中で、26件の教訓（何を間違えて、次にどう気をつけたか）と、複数のバックログ項目（今はやらないと決めたこと）が積み上がりました。しかし、**それをそのまま渡すと、あなたは他人の教訓を「従うべきルール」として受け取ってしまい、自分で同じ失敗に気づいて学ぶ機会を失います。** 渡す価値があるのは教訓の中身ではなく、**教訓を蓄積する仕組みと習慣**そのものです。

- **`LESSONS.md`**: 作業の節目（1日の終わり等）に、その日に起きたことを振り返り、「次に似た場面が来たらどう振る舞うべきか」という**再利用可能な教訓だけ**を抽出して追記していく場所です。その日限りの事実は書きません。ファイル内に書き方の型を用意してあります。
- **`BACKLOG.md`**: 「今回はやらない」と判断したことを、**理由とともに**記録する場所です。ファイル内に書き方の型を用意してあります。

⚠️ **なぜ結論だけでなく理由を残すのか——これは最も重要な原則の1つです。** 理由が無いと、後から誰か（未来の自分を含む）が「なぜこうなっているのか分からない」と、同じ検討を最初からやり直したり、良かれと思って元に戻してしまったりします。**結論と理由をセットで残すこと自体が、この2つのファイルが存在する意味です。**

## 4. 最初に何をすればよいか（この順番で）

いきなり全部埋める必要はありません。**最小限、これだけ埋めれば動き出せます**:

1. **`input/profile/01_基本情報.md`** — 氏名・連絡先など。5分で埋まります。
2. **`input/profile/02_学歴職歴.md`** — 学歴と職歴の年表。ここがキャリアの背骨になります。
3. **`input/profile/04_職務経歴.md`** — 一番時間がかかる部分です。案件（担当した仕事）ごとに「背景・課題 → 施策 → 成果」で書いてください。**最初は1〜2案件だけでも構いません。** 埋まった分から使えます。
4. **`input/apply/07_応募先.md`** — 応募したい求人票（JD）を貼り付けてください。特定の応募先が決まっていない段階なら、この手順は後回しにしてよいです。
5. **`input/apply/06_志望動機_希望条件_{接尾辞}.md`**（`07`で決めた接尾辞に合わせてファイル名を作る） — なぜこの会社か、を書いてください。

ここまで埋めたら、エージェントに **「履歴書と職務経歴書を生成して」** と伝えてください。まず動くものができます。

`input/profile/03_免許資格.md`・`05_スキル.md`、`input/apply/志望動機/00_不変の軸.md`・`ロール_{職種名}.md` は、書類の精度を上げる項目です。並行して、あるいは後から埋めていけば大丈夫です。

## 5. 全体の流れ

```
input/          documents/                  面接準備
（事実の正本） →（提出用に取捨選択・生成）→ interview/
   │                    │
   │            python3 scripts/build_pdf.py
   │                    │
   └── 経歴・志望動機の  documents/output/pdf/
       事実がここに      （提出用PDF）
       集まる
```

1. **`input/`** に事実を書く（経歴・資格・志望動機・希望条件）。ここが唯一の正本です。
2. エージェントが `documents/PROMPT.md` の手順に従って、`input/` の内容から**応募先向けに取捨選択**し、`documents/output/md/` に履歴書・職務経歴書のmdを作ります（**丸ごと転記ではなく、この応募先に効く部分を前に出す・関連の薄い部分は圧縮する**という編集が入ります）。`documents/output/md/`には、`build_pdf.py`が期待する見出し構成だけを示した空の雛形が最初から置いてあります——これをコピーして中身を埋めていく形で使ってください。
3. `python3 scripts/build_pdf.py` を実行すると、mdからPDFが生成されます（提出はこのPDFを使います）。
4. 選考が進んだら `interview/` で各ラウンドの準備・記録をします。書類と同じ`input/`を読むため、話す内容が書類とズレません。

**`input/`が変わったら、`documents/`側への反映が必要か都度考えてください。** ここは自動化されておらず（意図的な設計です——事実の全部を書類にそのまま載せるべきではないため）、人が判断して反映します。

## 6. `templates/` の5モジュール — いつ使うか

| モジュール | 使うタイミング |
|---|---|
| `templates/JD突き合わせ・経歴ヒアリング/` | 求人票と自分の経歴を突き合わせ、埋まっていない部分を洗い出したいとき |
| `templates/年収交渉フレーム/` | 希望年収を検討するとき、内定前後の交渉を準備するとき |
| `templates/推薦文ジェネレータ/` | リファラル（社内紹介）応募で、紹介者に推薦文を書いてもらう必要があるとき |
| `templates/模擬面接ジェネレータ/` | 書類が完成し、通常の読み直しでは粗が見つからなくなった段階で、AIエージェントに面接官役・自分役を演じさせて弱点を洗い出したいとき |
| `templates/提出前チェックリスト.md` / `日次終了チェックリスト.md` | 提出直前の最終確認／その日の作業を終えるとき |

それぞれのフォルダの`README.md`に詳しい使い方があります。**これらも「叩き台」です**——項目を足す・削る・言い回しを変える、自由にしてください。

## 7. AIエージェントへの最初の話しかけ方

`input/`を1〜2ファイルでも埋めたら、こう話しかけてください:

> `documents/PROMPT.md` に従って、`input/` の内容から履歴書と職務経歴書を生成してください。

特定の求人に向けて作りたい場合は、先に`input/apply/07_応募先.md`にJDを貼ってから:

> `input/apply/07_応募先.md` の求人票に向けて、書類を生成してください。

面接準備を始めたい場合は:

> `interview/INTERVIEW_PROMPT.md` に従って、◯◯社の△次面接の準備をしてください。

---

以降の作業で迷ったら、`README.md`（全体の地図）→ `documents/PROMPT.md` / `interview/INTERVIEW_PROMPT.md`（各作業の詳細ルール、ただし「叩き台」）→ `LESSONS.md`（自分で積み上げた教訓）の順に探してください。
