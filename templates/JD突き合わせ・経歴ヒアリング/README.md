# JD突き合わせ・経歴ヒアリング

> いつ使うか（トリガー）: **新しい応募先の求人票（JD）を入手したとき**、または**「不足している経歴情報を洗い出したい」「JDとの適合度を確認したい」と言われたとき**。

## このモジュールが解決すること

JDの要求と本人の経歴を突き合わせ、①応募可否を左右する絶対条件、②強い根拠がある項目、③部分的にしか対応しない項目、④根拠が無い項目に分ける。部分対応・根拠なしはヒアリングで確認し、埋まらない場合は「無いことをどう正直に、かつ不利にならない形で説明するか」の方針を決める。

**「材料を見つける」ことと「本人に何を聞くか」は同じ作業の裏表**——JDのギャップを分析した瞬間に、次に本人へ聞くべき質問がほぼ自動的に決まる。この一体化した流れがこのモジュールの核。

## 進め方

1. **ハードゲートを先に確認する**: 就労資格、入社可能時期、勤務地・出張、必須言語・資格など、満たせない場合に応募を止める条件を表にする。未確認は通過ではない。非通過があれば、例外承認なしに以後の作業を進めない
2. **JDから要求を抽出する**: 必須／歓迎と重要度（必須=5、主要業務=3、歓迎=1を目安）を付ける
3. **経歴データと照合し、重み付きで可視化する**（`input/profile/05_案件経験.md`・`04_スキル.md`等を参照):
   - **強い**: 具体的な案件・実績で直接示せる（100）
   - **部分的**: 近い経験はあるが、範囲・役割・実装段階が不足する（60）
   - **根拠なし**: 該当する経験が見当たらない（0）
   - 総合点は `Σ（重み × 点数）÷Σ重み`。これは比較と説明優先順位のための補助であり、合格確率や応募可否を自動判定しない
4. **ヒアリング質問を作る**（部分対応・根拠なしの項目について）:
   - 「本当に無いのか」を確認する質問と、「実は別の形であるのではないか」を掘る質問の両方を用意する
   - 優先度をつける（JDの必須要件に直結するものを最優先）
   - ⚠️ 質問の答えが「無い」であっても構わない。**無いことが分かることには価値がある**（★のまま残せる。教訓7参照）
5. **ヒアリング結果を反映する**: 経歴ファイル（`input/profile/`）に反映する。新事実は他の書類（`documents/output/{接尾辞}/md/`・`input/companies/{接尾辞}/06_志望動機_希望条件_{接尾辞}.md`・`input/apply/志望動機/`等）への伝播漏れが無いか横断確認する
6. **応募戦略を決める**: JDのどの要件を職務要約・自己PRの前方に配置するか、弱み（根拠なし項目）をどう説明するかを`07_応募先.md`相当のファイルにまとめる

## 使うときの注意

- **ヒアリングは1回で終わらせない。** 最初の回答が、スコープ、失敗と修正、数値の適用範囲など、次の事実を引き出す手掛かりになることが多い
- **本人が「弱み」と思っている点ほど、聞き方次第で強みに転換できることがある**（例: 「評価する側に立った経験」が「提案する側の視点に転用できる非対称な強み」に転換された）。ただし誇張はしないこと
